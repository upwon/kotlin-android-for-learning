读这种规模的代码，光靠看是不行的——你需要能**改一行、跑一下、看到差别**。
这一章把最短的那条路径铺好。

## 构建

工作区根在 `codex-rs/`，不在仓库根：

```bash
git clone https://github.com/openai/codex.git
cd codex/codex-rs
cargo build
cargo run --bin codex -- "explain this codebase to me"
```

仓库根有一个 `justfile`，它第一行就把工作目录设成了 `codex-rs`，
所以 `just` 命令在哪个目录跑都一样：

```bash
just codex          # = cargo run --bin codex --
just exec "..."     # = codex exec
just fmt            # 格式化 Rust + Bazel + Python
just test -p codex-tui   # 用 nextest 跑单个 crate 的测试
```

<Callout type="tip" title="只跑你动过的那个 crate 的测试">

`just test` 会跑全量，在这个体量下相当慢。`docs/install.md` 里明确建议
**不要**图省事加 `--all-features`——它会显著拉长构建时间并撑爆 `target/`。

</Callout>

## 两套构建系统

仓库同时有 `Cargo.toml` 和 `MODULE.bazel`。日常开发用 Cargo 就够了；
Bazel 那一套是给 CI 与远程缓存用的。两者的关系在 10.1 展开。

## 把内部事件打出来

Codex 用 `tracing`，靠环境变量控制：

```bash
# 只看 app-server 的 trace 级日志
RUST_LOG=codex_app_server=trace cargo run --bin codex

# 结构化输出，便于用 jq 过滤
LOG_FORMAT=json RUST_LOG=info cargo run --bin codex app-server
```

`RUST_LOG` 的目标名就是 crate 名把连字符换成下划线（`codex-app-server` → `codex_app_server`）。

## 三个最有用的 debug 子命令

`codex debug` 下面藏着一批本来是给内部开发用的工具，对读源码的人价值极高。

### 看最终发给模型的东西

```bash
codex debug prompt-input "帮我加个测试"
```

它会把**模型真正看到的那个输入列表**打成 JSON——包括系统提示、AGENTS.md 合进来的内容、
环境信息、注入的 skills。第 3.9 章讲提示词组装时，这个命令就是核对答案的地方。

<Callout type="warn" title="不要靠猜">

「模型为什么这么干」这类问题，八成能靠这一个命令直接定位。
先打出来看，再去读 `core/src/context_manager`。

</Callout>

### 手工给 app-server 发消息

```bash
codex debug app-server send-message-v2 "hello"
```

不用写客户端就能验证协议这一层是不是通的。想更完整地驱动，用 `just app-server-test-client`——
它会先构建 CLI，再用 `codex-app-server-test-client` 按协议跑一遍（见 10.2）。

### 单独试沙箱

```bash
codex debug seatbelt -- ls /etc     # macOS
codex debug landlock -- ls /etc     # Linux
```

把沙箱从整条链路里摘出来单独跑。第 5 部的每一章都可以配着它读。

## 自检

```bash
codex doctor
```

检查安装、配置、认证、沙箱可用性。它同时也是一份很好的**源码导览**：
`cli/src/doctor/` 里每一项检查，都对应着一个你迟早要读的子系统。

`codex debug prompt-input` 就是为这件事准备的：它把组装完成的、模型可见的输入列表原样打出来。

另外三个办法都能达到目的，但都更慢——尤其是重新编译，在这个体量下代价很实在。
读陌生代码库时，**先找它自带的观测出口**，通常比自己加日志快一个数量级。

</Quiz>

## 一句话结论

先让 `just`、`RUST_LOG`、`codex debug` 这三样跑通，再开始读代码，能省下一半时间。
