从 Java 转过来的人写出的第一版 Kotlin，通常是「用 Kotlin 语法写的 Java」——
能编译、能跑，但每一行都在浪费这门语言。这一课是一组对照，帮你校准手感。

<Callout type="java">

判断标准不是「短」，而是**意图是否直接可读**。下面每一组的 ✅ 版本都不只是更短，
而是把「我想干什么」写在了代码表面。

</Callout>

## 1. 用表达式代替赋值语句

```kotlin
fun describeJavaStyle(score: Int): String {
    var result: String
    if (score >= 90) {
        result = "优秀"
    } else if (score >= 60) {
        result = "及格"
    } else {
        result = "不及格"
    }
    return result
}

fun describeKotlinStyle(score: Int) = when {
    score >= 90 -> "优秀"
    score >= 60 -> "及格"
    else -> "不及格"
}

fun main() {
    println(listOf(95, 70, 30).map(::describeKotlinStyle))
}
```

关键差别不是行数，是 `var` 消失了。**能用 `val` 就没有中间状态可以出错。**

## 2. 用集合操作代替循环

```kotlin
data class Order(val id: Int, val amount: Int, val paid: Boolean)

fun main() {
    val orders = listOf(
        Order(1, 100, true),
        Order(2, 250, false),
        Order(3, 80, true),
        Order(4, 300, true),
    )

    // ❌ Java 风格
    var total = 0
    for (o in orders) {
        if (o.paid && o.amount > 50) {
            total += o.amount
        }
    }
    println(total)

    // ✅ Kotlin 风格：读起来就是需求本身
    val total2 = orders
        .filter { it.paid && it.amount > 50 }
        .sumOf { it.amount }
    println(total2)

    println(orders.groupBy { it.paid }.mapValues { (_, v) -> v.size })
    println(orders.maxByOrNull { it.amount })
    println(orders.any { !it.paid })
}
```

## 3. 用 apply / also 构建对象

```kotlin
class Config {
    var host: String = ""
    var port: Int = 0
    var timeoutMs: Long = 0
    override fun toString() = "Config($host:$port, ${timeoutMs}ms)"
}

fun main() {
    // ❌ 重复的接收者名字
    val c1 = Config()
    c1.host = "api.example.com"
    c1.port = 443
    c1.timeoutMs = 5000

    // ✅ apply：配置对象，返回对象本身
    val c2 = Config().apply {
        host = "api.example.com"
        port = 443
        timeoutMs = 5000
    }

    println(c2)
}
```

Android 上最典型的用法：

```kt
val intent = Intent(this, DetailActivity::class.java).apply {
    putExtra("id", id)
    putExtra("from", "list")
    flags = Intent.FLAG_ACTIVITY_CLEAR_TOP
}
startActivity(intent)
```

## 4. 空值处理的三段式

```kotlin
data class User(val name: String?, val city: String?)

fun main() {
    val user: User? = User("Summer", null)

    // 取值 + 兜底
    println(user?.name ?: "匿名")

    // 非空才执行一段逻辑
    user?.name?.let { println("欢迎 $it") }

    // 提前返回
    fun greet(u: User?): String {
        val name = u?.name ?: return "请先登录"
        return "你好，$name"
    }
    println(greet(user))
    println(greet(null))
}
```

<Callout type="warn" title="别把 let 当 if 用">

`?.let {}` 只在「确实需要一个非空的局部变量」时才划算。单纯判空做点事，`if` 更清楚：

```kt
// 😐 为了用 let 而用 let
user?.let { if (it.isVip) showBadge() }

// ✅ 直接写
if (user != null && user.isVip) showBadge()
```

</Callout>

## 5. 用扩展函数代替 Utils

```kotlin
// ❌ StringUtils.isValidPhone(phone)
// ✅ phone.isValidPhone()
fun String.isValidPhone(): Boolean =
    length == 11 && startsWith("1") && all { it.isDigit() }

fun <T> List<T>.secondOrNull(): T? = getOrNull(1)

fun main() {
    println("13800138000".isValidPhone())
    println(listOf("a", "b", "c").secondOrNull())
    println(listOf("a").secondOrNull())
}
```

## 6. 速查表

| 想做的事 | Java | Kotlin |
| --- | --- | --- |
| 三元运算 | `a > b ? a : b` | `if (a > b) a else b` |
| 字符串拼接 | `String.format(...)` | `"$name: $count"` |
| 判空取默认 | `x != null ? x : d` | `x ?: d` |
| 判空执行 | `if (x != null) {...}` | `x?.let { ... }` |
| 空/空白判断 | `StringUtils.isBlank(s)` | `s.isNullOrBlank()` |
| 集合过滤求和 | `stream().filter().sum()` | `filter { }.sumOf { }` |
| 单例 | `enum` / 双检锁 | `object Foo` |
| 常量 | `static final` | `const val`（顶层或 companion） |
| 惰性初始化 | 双检锁 | `by lazy { }` |
| 交换两个值 | 临时变量 | `a = b.also { b = a }` |
| 遍历带下标 | `for (int i...)` | `forEachIndexed { i, v -> }` |
| 多返回值 | 自定义类 | `data class` + 解构 |
| 区间判断 | `x >= 1 && x <= 9` | `x in 1..9` |
| 类型判断+转换 | `instanceof` + 强转 | `is` + smart cast |
| 资源自动关闭 | try-with-resources | `use { }` |

## 7. 几个高频小技巧

```kotlin
fun main() {
    // takeIf：条件成立才保留值，否则 null
    val input = "  hello  "
    println(input.trim().takeIf { it.isNotEmpty() } ?: "（空）")

    // 交换，不需要临时变量
    var a = 1
    var b = 2
    a = b.also { b = a }
    println("a=$a b=$b")

    // 区间与 in
    val age = 25
    println(age in 18..60)
    println("kot" in "kotlin")

    // 解构
    val (name, score) = "Summer" to 95
    println("$name -> $score")

    // 多行字符串
    val json = """
        {
          "name": "$name",
          "score": $score
        }
    """.trimIndent()
    println(json)
}
```

## 练习

<Quiz
  index={1}
  type="fill"
  question="把这段 Java 改写成一行 Kotlin：int total = 0; for (Order o : orders) { if (o.isPaid()) total += o.getAmount(); }"
  answer={[
    'val total = orders.filter { it.paid }.sumOf { it.amount }',
    'val total = orders.filter { it.paid }.sumOf { it.amount }',
  ]}
>

`filter` 挑出满足条件的元素，`sumOf` 把每个元素映射成数字再求和。

也可以写成 `orders.sumOf { if (it.paid) it.amount else 0 }`——只遍历一次，
但可读性稍差。集合不大时优先选前者；真的在意中间集合的开销，用
[Sequence](/docs/07-collections/sequences)。

</Quiz>

<Quiz
  index={2}
  question={
    <>
      <code>a = b.also {'{'} b = a {'}'}</code> 为什么能交换 a 和 b？
    </>
  }
  options={[
    'also 会自动交换接收者和参数',
    'also 的 lambda 先执行（此时 a 还是旧值），also 返回接收者 b 的原值再赋给 a',
    '这段代码其实是错的，a 和 b 会变成同一个值',
    '因为 also 返回 lambda 的结果',
  ]}
  answer={1}
>

拆开看求值顺序：

1. `b.also { ... }` 先拿到接收者 `b`（旧值 2）
2. 执行 lambda：`b = a`，此时 `a` 还是旧值 1，所以 `b` 变成 1
3. `also` 返回**接收者本身**（也就是步骤 1 记下的旧值 2）
4. 把 2 赋给 `a`

关键在于 `also` 返回的是接收者而不是 lambda 结果（那是 `let` 的行为），
且返回值在 lambda 执行前就确定了。

</Quiz>

<Quiz
  index={3}
  question="下面哪种写法更符合 Kotlin 习惯？"
  options={[
    'user?.let { if (it.isVip) showBadge() }',
    'if (user != null && user.isVip) showBadge()',
    '两者完全等价，随便选',
    'user!!.let { if (it.isVip) showBadge() }',
  ]}
  answer={1}
>

B。`?.let {}` 的价值在于「拿到一个非空的局部变量，然后用它做几件事」。
这里只是判空后做一次判断，`if` 更直接——而且 smart cast 让 `user.isVip`
在 `&&` 右边完全合法，不需要 `it`。

「会用某个特性」和「该用某个特性」是两回事。滥用作用域函数是 Kotlin 代码可读性变差的头号原因，
[7.6](/docs/07-collections/scope-functions) 会给出完整的选择依据。

D 里的 `!!` 更是把编译期保证换成了运行时崩溃。

</Quiz>

<Quiz
  index={4}
  type="multi"
  question="以下哪些改写是有实质收益的（而不只是更短）？"
  options={[
    '把 if-else 赋值改成 when 表达式，从而把 var 变成 val',
    '把 Utils 静态方法改成扩展函数，让调用点读起来像方法链',
    '把所有 for 循环都改成 forEach',
    '用具名实参代替连续多个布尔参数',
  ]}
  answer={[0, 1, 3]}
>

- **A**：消灭了一个 `var`，也就消灭了「中间状态被改错」的可能。
- **B**：调用点从 `StringUtils.isValidPhone(p)` 变成 `p.isValidPhone()`，可以自然地接进链式调用。
- **D**：`createUser("Summer", true, false, true)` 这种调用，不查签名根本读不懂。

**C 没有收益**，甚至常有负收益：`forEach` 里不能用 `break`/`continue`
（只能 `return@forEach` 模拟 continue），而且带索引时不如 `for` 直观。
`for` 在 Kotlin 里是完全正当的写法。

</Quiz>
