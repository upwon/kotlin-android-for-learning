`object` 一个关键字承担了 Java 里三件不同的事：**匿名内部类**、**单例**、**静态成员**。
理解「Kotlin 没有 static」这个设计选择，是这一课的核心。

## 1. 对象表达式 = 匿名内部类

```kotlin
interface ClickListener {
    fun onClick(id: Int)
    fun onLongClick(id: Int): Boolean
}

fun main() {
    // 多个方法的接口，只能用对象表达式
    val listener = object : ClickListener {
        override fun onClick(id: Int) = println("点击 $id")
        override fun onLongClick(id: Int): Boolean {
            println("长按 $id")
            return true
        }
    }
    listener.onClick(1)
    listener.onLongClick(2)

    // 也可以不继承任何类型，临时凑一个对象
    val temp = object {
        val x = 1
        val y = 2
    }
    println(temp.x + temp.y)
}
```

<Callout type="warn" title="对象表达式每次求值都创建新实例">

```kotlin
class Factory {
    fun create() = object { val id = System.nanoTime() }
}

fun main() {
    val f = Factory()
    println(f.create() === f.create())   // false，两个不同对象
}
```

这和 `object` **声明**（单例）完全不同，别混淆：
`object : Type { }` 出现在表达式位置是「创建一个匿名对象」，
`object Name { }` 出现在声明位置是「定义一个单例」。

</Callout>

## 2. 对象声明 = 线程安全的单例

```kotlin
object AppConfig {
    var baseUrl: String = "https://api.example.com"
    private var initialized = false

    fun init(url: String) {
        baseUrl = url
        initialized = true
    }

    fun status() = "url=$baseUrl, initialized=$initialized"
}

fun main() {
    println(AppConfig.status())
    AppConfig.init("https://test.example.com")
    println(AppConfig.status())
    println(AppConfig === AppConfig)   // 永远是同一个实例
}
```

<Callout type="java" title="它编译成什么">

一个带 `public static final INSTANCE` 字段的类，实例在**静态初始化块**里创建。

```java
// Java 侧调用
AppConfig.INSTANCE.getBaseUrl();
```

由 JVM 的类加载机制保证**线程安全**和**懒加载**（第一次访问时才初始化）——
就是经典的「静态内部类单例」模式，只不过语言帮你写好了。

不需要双检锁，不需要 `volatile`，也不会有 DCL 的各种坑。

</Callout>

`object` 可以继承类和实现接口：

```kotlin
interface Logger {
    fun log(msg: String)
}

object ConsoleLogger : Logger {
    override fun log(msg: String) = println("[LOG] $msg")
}

fun main() = ConsoleLogger.log("hello")
```

## 3. companion object：Kotlin 没有 static

```kotlin
class User private constructor(val name: String) {

    companion object {
        const val MAX_NAME_LENGTH = 20      // 编译期常量

        private var count = 0

        fun create(name: String): User? {
            if (name.length > MAX_NAME_LENGTH) return null
            count++
            return User(name)
        }

        fun createdCount() = count
    }
}

fun main() {
    println(User.create("Summer")?.name)
    println(User.create("x".repeat(30))?.name)
    println(User.createdCount())
    println(User.MAX_NAME_LENGTH)
}
```

<Callout type="warn" title="companion object 是一个真实的对象">

这不只是语法差异。`companion object` 是类里的一个**嵌套单例对象**，
它可以：

```kotlin
interface Factory<T> {
    fun create(): T
}

class Widget {
    companion object : Factory<Widget> {      // ✅ 可以实现接口
        override fun create() = Widget()
    }
}

fun main() {
    val f: Factory<Widget> = Widget            // 伴生对象可以当值传递
    println(f.create())
}
```

Java 的 `static` 成员做不到这些——它们不是对象，不能实现接口，不能作为值传递。

代价是：`companion object` 的成员**默认不是真正的静态方法**，
Java 侧要写 `Widget.Companion.create()`。

</Callout>

## 4. Java 互操作：@JvmStatic 和 @JvmField

```kt
class Analytics {
    companion object {
        @JvmStatic
        fun track(event: String) { }        // Java: Analytics.track("x")

        fun trackNoAnno(event: String) { }  // Java: Analytics.Companion.trackNoAnno("x")

        @JvmField
        val VERSION = "1.0"                 // Java: Analytics.VERSION

        val versionNoAnno = "1.0"           // Java: Analytics.Companion.getVersionNoAnno()

        const val BUILD = 100               // Java: Analytics.BUILD（const 自带这个效果）
    }
}
```

| 注解 | 作用 |
| --- | --- |
| `@JvmStatic` | 生成真正的静态方法 |
| `@JvmField` | 暴露为公开字段，不生成 getter |
| `const val` | 编译期常量，天然就是静态字段 |

<Callout type="tip">

规则很简单：**这个成员会被 Java 调用吗？会就加注解。**

Android 上典型的例子是 Fragment 的 `newInstance()`——如果项目里还有 Java 代码
会调用它，就该加 `@JvmStatic`。

</Callout>

## 5. object 与内存泄漏

<Callout type="warn" title="Android 上最需要警惕的一点">

`object` 单例的生命周期是**整个进程**。往里面存任何带 Context 的东西都是泄漏：

```kt
// ❌ Activity 永远无法被回收
object UserManager {
    var currentActivity: Activity? = null
    lateinit var context: Context
}

// ✅ 只存 applicationContext
object UserManager {
    private lateinit var appContext: Context

    fun init(context: Context) {
        appContext = context.applicationContext   // ← 关键
    }
}
```

同样危险的是往单例里注册回调而不注销：

```kt
// ❌ Fragment 被单例持有，无法回收
object EventBus {
    private val listeners = mutableListOf<(String) -> Unit>()
    fun register(l: (String) -> Unit) { listeners += l }
}
```

**更好的做法是别用 `object` 做单例**，改用依赖注入：

```kt
@Singleton
class UserManager @Inject constructor(
    @ApplicationContext private val context: Context,
)
```

Hilt 管理生命周期，同时可测试（能注入 fake 实现）——
而 `object` 单例的状态会在测试之间泄漏，是单元测试里最常见的「测试相互影响」来源。

</Callout>

## 6. 选择哪一个

```kotlin
// 1. 无状态的工具集合 → 顶层函数（首选！）
fun formatPrice(cents: Int) = "¥%.2f".format(cents / 100.0)

// 2. 需要命名空间分组的常量 → object
object ApiPath {
    const val LOGIN = "/api/login"
    const val LOGOUT = "/api/logout"
}

// 3. 与某个类强相关的工厂方法 / 常量 → companion object
class Fragment2 {
    companion object {
        private const val ARG_ID = "arg_id"
        fun newInstance(id: Long) = Fragment2()
    }
}

fun main() {
    println(formatPrice(12345))
    println(ApiPath.LOGIN)
    println(Fragment2.newInstance(1))
}
```

<Callout type="warn" title="别把 object 当 Utils 类用">

从 Java 带来的习惯：

```kt
// 😐 没必要，多了一层 StringUtils.
object StringUtils {
    fun isPhone(s: String) = s.length == 11
}

// ✅ 顶层函数
fun isPhone(s: String) = s.length == 11

// ✅✅ 扩展函数更好
fun String.isPhone() = length == 11
```

只有当这些函数**需要共享状态**，或者**命名空间确实有价值**（同名函数太多）时，
才用 `object` 包一层。

</Callout>

## 练习

<Quiz
  index={1}
  question={
    <>
      <code>object Foo</code> 的线程安全和懒加载是怎么保证的？
    </>
  }
  options={[
    '编译器生成了双检锁代码',
    '编译成带 static final INSTANCE 字段的类，由 JVM 类加载机制保证',
    '用 synchronized 关键字',
    '不保证，需要自己加锁',
  ]}
  answer={1}
>

`object Foo` 编译成一个含 `public static final Foo INSTANCE` 的类，
实例在**静态初始化块**里创建。

JVM 规范保证类的初始化是**线程安全**的，且发生在**第一次主动使用**时——
这正是经典的「静态内部类单例」模式，语言帮你写好了。

所以不需要双检锁、不需要 `volatile`，也不会遇到 DCL 的指令重排问题。

</Quiz>

<Quiz
  index={2}
  question={
    <>
      Java 里调用 Kotlin 的 <code>companion object</code> 方法，默认要怎么写？
    </>
  }
  options={[
    'MyClass.method()',
    'MyClass.Companion.method()',
    'MyClass.INSTANCE.method()',
    '无法调用',
  ]}
  answer={1}
>

`MyClass.Companion.method()`。因为 `companion object` 是一个**真实的嵌套对象**，
不是 Java 的静态成员。

想让 Java 侧写成 `MyClass.method()`，给方法加 `@JvmStatic`；
属性加 `@JvmField`（或者用 `const val`，它天然就是静态字段）。

顺带一提，`companion object` 是真实对象带来了 Java static 没有的能力：
它可以实现接口、可以作为值传递、可以有扩展函数。

</Quiz>

<Quiz
  index={3}
  question="Android 上用 object 单例最大的风险是什么？"
  options={[
    '性能问题',
    '生命周期是整个进程，持有 Activity/Context 会导致内存泄漏；且状态会在单元测试间泄漏',
    '不能实现接口',
    '不是线程安全的',
  ]}
  answer={1}
>

两个风险：

1. **内存泄漏**：`object` 活到进程结束。存了 Activity、View、Fragment 或者
   非 application 的 Context，这些对象就永远回收不了。存 Context 必须用
   `context.applicationContext`。
2. **测试污染**：单例状态在测试用例之间共享，导致「单独跑通过、一起跑失败」
   这类最难查的问题。

更好的做法是用依赖注入（Hilt 的 `@Singleton`）：生命周期由容器管理，
测试时能注入 fake 实现。

</Quiz>

<Quiz
  index={4}
  question={
    <>
      <code>object : Type {'{'} ... {'}'}</code>（对象表达式）每次求值会怎样？
    </>
  }
  options={[
    '返回同一个单例',
    '每次创建一个新实例',
    '编译错误',
    '第一次创建，之后缓存',
  ]}
  answer={1}
>

**每次创建新实例**——对象表达式相当于 Java 的匿名内部类，出现在表达式位置。

这和 `object Name { }`（对象**声明**，出现在声明位置）是两回事，后者才是单例。
同一个关键字承担了两种语义，靠出现的位置区分：

- 声明位置 → `object AppConfig { }` → 单例
- 表达式位置 → `val x = object : Listener { }` → 匿名对象，每次新建

另外要注意：对象表达式如果定义在类内部且引用了外部成员，它会**持有外部类的引用**——
Android 上把它注册到长生命周期的地方（比如单例的监听器列表）同样会泄漏。

</Quiz>
