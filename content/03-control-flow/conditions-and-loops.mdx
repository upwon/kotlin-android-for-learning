这一课的核心只有一句话：**`if` 和 `when` 是表达式，有返回值。**
这一个差异会连锁改变你写分支逻辑的方式——`var` 会大幅减少，三元运算符不再需要，
`switch` 升级成了模式匹配的雏形。

## 1. if 是表达式

```kotlin
fun main() {
    // 取代三元运算符（Kotlin 没有 ?: 三元语法，Elvis 是另一回事）
    val max = if (3 > 5) 3 else 5
    println(max)

    // 块体时，最后一个表达式是返回值
    val grade = if (85 >= 60) {
        println("判定中…")
        "及格"
    } else {
        "不及格"
    }
    println(grade)
}
```

<Callout type="java" title="为什么 Kotlin 没有三元运算符">

因为 `if` 本身就有返回值，三元运算符就变成了多余的语法。
`if (a) b else c` 只比 `a ? b : c` 长几个字符，却少了一套需要记的规则。

</Callout>

<Callout type="warn" title="作为表达式用时，else 不能省">

```kt
val x = if (a > b) a          // ❌ 编译错误：'if' must have both main and 'else' branches
```

道理很简单：条件不成立时这个表达式该取什么值？语言不会替你编一个。

但**作为语句用**时（不取返回值），`else` 可以省：

```kt
if (a > b) println("a 更大")   // ✅ 合法
```

</Callout>

## 2. when：switch 的超集

```kotlin
fun describe(x: Any): String = when (x) {
    0, 1 -> "0 或 1"                    // 多个值
    in 2..9 -> "个位数"                  // 区间
    !in 10..99 -> "不是两位数"            // 取反区间
    is String -> "字符串，长度 ${x.length}"  // 类型（并自动 smart cast）
    else -> "其他：$x"
}

fun main() {
    listOf(0, 5, 42, 1000, "hi").forEach { println(describe(it)) }
}
```

**无参数形式**——当作条件链用，比一串 `else if` 清楚：

```kotlin
fun grade(score: Int): String = when {
    score >= 90 -> "优秀"
    score >= 80 -> "良好"
    score >= 60 -> "及格"
    else -> "不及格"
}

fun main() {
    println(listOf(95, 85, 70, 30).map(::grade))
}
```

**带主语的形式**（Kotlin 1.3+），可以在 `when` 里声明变量：

```kotlin
fun main() {
    val result = when (val length = "Kotlin".length) {
        in 0..3 -> "短：$length"
        in 4..10 -> "中：$length"
        else -> "长：$length"
    }
    println(result)
}
```

## 3. 穷尽性 exhaustive

这是 `when` 相对 `switch` 最有价值的地方：

```kotlin
sealed interface UiState {
    data object Loading : UiState
    data class Success(val count: Int) : UiState
    data class Error(val message: String) : UiState
}

// 覆盖了所有子类，不需要 else
fun render(state: UiState): String = when (state) {
    UiState.Loading -> "加载中"
    is UiState.Success -> "成功，${state.count} 条"
    is UiState.Error -> "失败：${state.message}"
}

fun main() {
    println(render(UiState.Loading))
    println(render(UiState.Success(3)))
    println(render(UiState.Error("超时")))
}
```

<Callout type="success" title="不要给 sealed 的 when 加 else">

加了 `else` 就等于放弃了穷尽性检查。以后往 `UiState` 里新增一个
`Empty` 分支时：

- **没有 else**：所有 `when` 立刻编译报错，编译器带你逐个去补 → 这正是你要的
- **有 else**：静默走进 `else`，运行时才发现 UI 不对

同理，`enum` 上的 `when` 也遵循这条。这是 Kotlin 里最实用的重构安全网之一。

</Callout>

<Callout type="warn">

注意：`when` **作为语句**（不取返回值）时，早期版本不强制穷尽。
Kotlin 1.7 起对 sealed / enum / Boolean 的非穷尽 `when` 语句会报**警告**，
从 2.0 起变成**错误**。这是好事——照着修就行。

</Callout>

## 4. for 与区间

Kotlin 没有 C 风格的 `for (int i = 0; i < n; i++)`，只有 for-each：

```kotlin
fun main() {
    // 区间
    for (i in 1..5) print("$i ")          // 1 2 3 4 5，闭区间
    println()
    for (i in 1..<5) print("$i ")         // 1 2 3 4，开区间（1.9+，旧写法 until）
    println()
    for (i in 5 downTo 1) print("$i ")    // 倒序
    println()
    for (i in 1..10 step 3) print("$i ")  // 步长
    println()

    // 集合
    val items = listOf("a", "b", "c")
    for (item in items) print("$item ")
    println()
    for (i in items.indices) print("$i ")           // 下标
    println()
    for ((i, v) in items.withIndex()) print("$i=$v ")  // 下标+值
    println()

    // Map 解构
    val map = mapOf("x" to 1, "y" to 2)
    for ((k, v) in map) print("$k->$v ")
}
```

<Callout type="warn" title="downTo 不能和 .. 混用">

```kt
for (i in 5..1) { }          // ❌ 不报错，但一次都不执行（空区间）
for (i in 5 downTo 1) { }    // ✅ 倒序要用 downTo
```

`5..1` 是一个合法但**空**的区间。这是个静默 bug，写倒序循环时要留神。

</Callout>

`..<`（或 `until`）在遍历下标时最常用，因为它天然避免了 off-by-one：

```kotlin
fun main() {
    val list = listOf("a", "b", "c")
    for (i in 0..<list.size) print("${list[i]} ")   // 0,1,2
    println()
    // 但其实这样更好
    for (i in list.indices) print("${list[i]} ")
}
```

## 5. while 与 do-while

和 Java 完全一致，没有差异：

```kotlin
fun main() {
    var i = 0
    while (i < 3) {
        print("$i ")
        i++
    }
    println()

    do {
        print("至少执行一次 ")
    } while (false)
}
```

## 6. 区间不只用于循环

`in` 是一个独立的运算符（背后是 `contains`），可以脱离循环单独用：

```kotlin
fun main() {
    val age = 25
    println(age in 18..60)              // 比 age >= 18 && age <= 60 清楚
    println(age !in 0..17)

    println('c' in 'a'..'z')
    println("kot" in "kotlin")          // 字符串包含
    println(3 in listOf(1, 2, 3))       // 集合包含

    // when 里用
    val level = when (age) {
        in 0..12 -> "儿童"
        in 13..17 -> "青少年"
        in 18..59 -> "成年"
        else -> "老年"
    }
    println(level)
}
```

## 7. Android 场景

<Callout type="tip" title="when 建模 UI 状态与事件分发">

```kt
// ViewModel 里分发用户事件
fun onEvent(event: LoginEvent) = when (event) {
    is LoginEvent.UsernameChanged -> updateUsername(event.value)
    is LoginEvent.PasswordChanged -> updatePassword(event.value)
    LoginEvent.Submit -> submit()
    LoginEvent.Dismiss -> dismiss()
}

// Fragment 里渲染状态
private fun render(state: UiState) = when (state) {
    UiState.Loading -> binding.progress.isVisible = true
    is UiState.Success -> showList(state.items)
    is UiState.Error -> showError(state.message)
}
```

新增一个事件类型时，编译器会强制你在 `onEvent` 里处理它——比运行时才发现「这个按钮没反应」
强太多。

</Callout>

<Callout type="warn" title="别在 RecyclerView 的热路径上滥用区间对象">

`for (i in 0..<n)` 在编译后会被优化成普通的索引循环，**没有额外开销**。
但下面这种会真的创建对象：

```kt
val range = 0..<n          // 创建了一个 IntRange 对象
list.filter { it in range }
```

一般无所谓，只有在 `onBindViewHolder` / `onDraw` 里高频执行时才值得关心。

</Callout>

## 练习

<Quiz
  index={1}
  question={
    <>
      为什么 <code>val x = if (a &gt; b) a</code> 编译不过？
    </>
  }
  options={[
    '因为 if 不能用于赋值',
    '因为作为表达式使用时必须有 else，否则条件不成立时没有值可返回',
    '因为缺少类型声明',
    '因为 a 和 b 类型不同',
  ]}
  answer={1}
>

`if` 作为**表达式**（要取返回值）时必须有 `else`——否则条件为假时这个表达式没有值。

但作为**语句**用（不取返回值）时完全可以省略 `else`：

```
if (a > b) println("a 更大")     // ✅
```

顺带一提，这也是 Kotlin 不需要三元运算符的原因：`if (a) b else c` 已经承担了那个角色。

</Quiz>

<Quiz
  index={2}
  question="对 sealed class 做 when 时，为什么不建议加 else？"
  options={[
    '加了 else 会有性能损耗',
    '加了 else 就放弃了穷尽性检查，新增子类时不会编译报错而是静默走 else',
    'sealed class 不允许有 else',
    '因为 else 分支永远不会被执行',
  ]}
  answer={1}
>

`sealed` + `when` 的最大价值是**重构安全网**：子类集合在编译期已知，
覆盖全了就是穷尽的，不需要 `else`。

一旦加了 `else`，编译器就认为你已经处理了所有情况。将来往层级里加一个新子类时：

- 没有 `else` → 所有 `when` 立刻编译报错，带着你逐个去补
- 有 `else` → 静默落入 `else`，运行时才发现界面不对

这在 UI State / Event 建模上收益极大——加一个新状态，编译器会告诉你所有需要更新的地方。

</Quiz>

<Quiz
  index={3}
  question={
    <>
      <code>for (i in 5..1) print(i)</code> 会输出什么？
    </>
  }
  options={[
    '5 4 3 2 1',
    '1 2 3 4 5',
    '什么都不输出',
    '编译错误',
  ]}
  answer={2}
>

什么都不输出。`5..1` 是一个合法但**空**的区间——`..` 只能递增，起点大于终点时区间为空。

倒序必须用 `downTo`：`for (i in 5 downTo 1)`。

这是个典型的**静默 bug**：不报错、不崩溃，循环体一次都不执行。写倒序遍历时要特别留意。

</Quiz>

<Quiz
  index={4}
  type="multi"
  question="关于 when，哪些说法正确？"
  options={[
    '可以匹配区间，如 in 1..9',
    '可以匹配类型，且分支内会自动 smart cast',
    '不带参数时可以当作 if-else if 链使用',
    '所有 when 都必须有 else 分支',
  ]}
  answer={[0, 1, 2]}
>

A、B、C 都对，这三点正是 `when` 相对 Java `switch` 的升级：能匹配区间、
能匹配类型（且自动 smart cast，分支内直接用具体类型的成员）、
不带参数时是任意布尔条件链。

**D 错**：当 `when` 已经穷尽时不需要 `else`——对 `sealed` 层级覆盖了全部子类、
对 `enum` 覆盖了全部常量、对 `Boolean` 覆盖了 true/false，都属于穷尽。
而且这种情况下**不该**加 `else`。

</Quiz>
